OS イメージの作り方

脆弱な Web サーバ 1 つ、SSH で入る 1 台など、サービスを OS に直接入れた VM を作る場合はこちら。 ゲストカーネルと rootfs をそれぞれ指定します（デフォルト資産 / アップロード / URL）。

rootfs

  • ext4: 完成した ext4 イメージをそのまま使う
  • tar: docker export したファイルシステム tar をアップロードすると、 自動的に ext4 へ変換される（docker save 形式は非対応）
  • tar から作る場合、起動後にサービスを立ち上げる /sbin/init を自分で用意する必要がある （カーネルは CMD/ENTRYPOINT を使わず /sbin/init を実行する）

カーネル

既定の Firecracker 公式カーネルで足りる。カーネル CVE を扱う問題だけ、 プロジェクト専用の脆弱なカーネルをアップロードする。

手順

  1. 新規プロジェクト作成で「OS イメージ」を選ぶ
  2. カーネル・rootfs それぞれを「デフォルト資産を使う」「アップロード」「URL」のいずれかで指定する
  3. rootfs が tar の場合は自動的に ext4 へ変換される（pending/converting の間は起動不可）
  4. ready になれば起動可能

複数のサービス（Web + DB + LB など）を 1 台で動かす場合は Compose バンドルの作り方 →
