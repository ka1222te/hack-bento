OS イメージの作り方

脆弱な Web サーバ 1 つ、SSH で入る 1 台など、サービスを OS に直接入れた VM を作る場合に使う形式です。 ゲストカーネルと rootfs をそれぞれ指定します。

1. rootfs を用意する

ext4
完成した ext4 イメージをそのままアップロードする。変換処理は不要。
tar
docker export で書き出したファイルシステム tar をアップロードすると、 サーバ側で自動的に ext4 へ変換される。
※ docker save 形式（複数レイヤーの OCI アーカイブ）は非対応
tar から作る場合は、起動後にサービスを立ち上げる /sbin/init を自分で用意する必要がある （ゲストカーネルは CMD/ENTRYPOINT を使わず、常に /sbin/init を実行する）。

2. カーネルを用意する

既定
Firecracker 公式カーネルで足りる。通常はこれを選べばよい。
専用
カーネル CVE を扱う問題だけ、プロジェクト専用の脆弱なカーネルをアップロードする。

3. プロジェクトを作成する

  1. プロジェクト作成ページに戻る
  2. カーネル・rootfs それぞれを「デフォルト資産を使う」「アップロード」「URL」のいずれかで指定する
  3. rootfs が tar の場合は自動的に ext4 へ変換される
  4. ready になれば起動可能
