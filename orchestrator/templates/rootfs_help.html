rootfs の作り方

HackBento は Firecracker microVM で環境を起動します。登録するプロジェクトには 「OS イメージ」と「Compose バンドル」の 2 形式があります。

A. Compose バンドル（推奨・手軽）

手元で docker compose up が通る構成を、そのまま VM 1 台として配布できます。 VM の中で Docker が動き、ports: で公開したポートが VM の IP で待ち受けます （例: 192.168.181.200:80）。

  1. 手元で compose プロジェクトを用意し動作確認する
  2. 付属ツールを取得する（クローン不要・root 不要。認証なしで取得できる）: 
    curl -fsSL {{ request.url.scheme }}://{{ request.url.netloc }}/static/tools/hackbento-pack -o hackbento-pack
chmod +x hackbento-pack
  3. バンドル tar を作る: 
    ./hackbento-pack --bundle ./my-ctf -o my-ctf.bundle.tar
  4. 新規プロジェクト作成で「Compose バンドル」を選び、tar をアップロード
  5. サーバがネットワークなしのビルド用 VM の中で ext4 を組み立て、ready になれば起動可能

注意点

  • 各サービスに image: を指定する（build: のみは不可。pack が build/pull してイメージを同梱する）
  • macvlan/ipvlan ネットワークや固定 IP（ipv4_address）は使えない（VM の IP は 1 つ）。公開は ports: で行う
  • ゲスト OS 側にフラグや設定ミスを仕込みたい場合は、プロジェクト直下の overlay/ に置く （例: overlay/root/flag.txt → VM の /root/flag.txt）
  • 名前付きボリュームや DB の初期化は VM 起動のたびにまっさらから始まる（CTF に好適）

B. OS イメージ（中で Docker を使わない 1 台）

脆弱な Web サーバ 1 つ、SSH で入る 1 台など、サービスを OS に直接入れた VM を作る場合はこちら。 ゲストカーネルと rootfs をそれぞれ指定します（デフォルト資産 / アップロード / URL）。

  • rootfs（ext4）: 完成した ext4 イメージをそのまま使う
  • rootfs（tar）: docker export したファイルシステム tar をアップロードすると、 自動的に ext4 へ変換される（docker save 形式は非対応）
  • tar から作る場合、起動後にサービスを立ち上げる /sbin/init を自分で用意する必要がある （カーネルは CMD/ENTRYPOINT を使わず /sbin/init を実行する）
  • カーネル: 既定の Firecracker 公式カーネルで足りる。カーネル CVE を扱う問題だけ、 プロジェクト専用の脆弱なカーネルをアップロードする

どちらを選ぶか

  • 複数のサービス（Web + DB + LB など）を 1 台で動かす → Compose バンドル
  • 1 つのサービス / OS を直接作る、カーネル CVE を扱う → OS イメージ
